# I022 — 개조식 보고서의 그림 단독 페이지와 짧은 마지막 페이지

## 2026-11-07 추가 관찰 — 변경 절 제목 분리

P78 직접 작업 설명을 보완한 PDF를 렌더하였더니 그림 아래에 ‘3 기능 설정과 변경’ 제목만 남고 첫 변경 표가 다음 페이지로 이동하였음. 제목과 첫 변경 전후 표를 함께 묶어 페이지를 넘기는 조치가 필요함. 본문 크기·여백·필수 내용을 줄이지 않고 기존 렌더러의 묶음 배치를 적용할 예정임.

상태: 해결·재검증 완료. 2026-11-06 KST.

## 관찰·재현

사용자 요청에 따라 보고서 원문 58개 문단을 171개 개조식 항목으로 분리했다. 공백을 제외한 원문 텍스트와 표·그림 목록은 동일하다. 최초 렌더는 11쪽이며 그림 1·2가 각각 단독 페이지를 차지하고 마지막 11쪽에는 약 198자의 짧은 항목만 남았다. 내용 누락·암호·A4 경계 오류 검사는 통과했지만 전체 페이지 몽타주에서 여백과 내용 분산을 확인했다.

## 기대 결과·영향

필수 8개 목차·본문 10pt·표·그림·원문 사실·수치·링크를 유지하며, 관련 그림을 함께 배치하고 마지막 절이 짧게 분리되지 않게 한다. 보고서 페이지 수 제한은 없으나 불필요한 단독 페이지는 읽기 어렵게 한다.

## 원인 판단·수정 계획

기존 그림을 각각 KeepTogether로 추가하던 방식과 문단별 항목 간격이 개조식의 길이에 그대로 적용됐다. 두 홈 화면은 한 행으로 묶고 그림 크기·항목 간격·마지막 절의 시작 여유를 조정한 뒤 전체 페이지를 다시 렌더해 확인한다. 본문 축소나 원문 삭제로 해결하지 않는다.

## 첫 배치 시도의 실제 실패

두 이미지를 표의 한 행에 넣은 첫 수정은 ReportLab LayoutError로 실패했다. 지정한 폭과 달리 가장 높은 행이 920pt로 계산됐다. Image의 지연 초기화가 크기 속성을 처음 읽을 때 drawWidth를 원본 값으로 다시 설정하는 전제를 확인했다. 이 상태를 성공 PDF로 취급하지 않는다. 이미지의 원본 크기를 먼저 읽은 뒤 표시 크기를 지정하고, 생성 성공 후에만 최종 PDF를 교체하도록 보완한다.

## 수정·재검증

원본 크기를 먼저 읽고 표시 폭·높이를 지정했다. 그림 1·2는 한 행, 그림 3은 그 아래에 배치했다. 항목 간격을 통일하고 AI 사례의 제목·목적·요청을 함께 유지하며 마지막 출처 절을 묶었다. 본문은 10pt, 필수 목차는 8개 그대로다. 원문 58개 문단을 분리한 171개 항목은 공백을 제외하고 모두 동일하며 표·그림 목록도 동일하다. 9쪽 전체의 렌더·A4 경계·암호·최종 SHA·증빙 링크를 확인했다. 링크 주석 수는 줄바꿈 병합에 따라 40개에서 39개로 바뀌었으나 고유 URI 26개는 모두 동일하다. 최종 main 배포 뒤 SHA·배포 정보만 갱신해 다시 내보낸다.
