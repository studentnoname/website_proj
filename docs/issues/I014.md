# I014 — #intro로 접속하면 첫 화면의 글 등장이 생략됨

상태: 수정·입장 조건 재검증 완료. 2026-11-04 KST. 수정 전 기록: `6752213`.

사용자의 반복된 “똑같아” 보고 후 공개 주소에서 별도 Firefox 프로필로 확인했다. 사이트 효과를 켜고 즉시 조회한 결과 일반 루트는 hero 애니메이션 7개, `#intro`와 `#current`는 0개였다. 세 경우 모두 `data-pf-motion=on`이었다. `#current`의 생략은 읽는 목적지를 우선하는 의도된 동작이지만, 첫 화면 자체인 `#intro`까지 생략한 것은 접속 시 순차 등장 요구와 맞지 않는다. 아직 사용자 접속 주소 답변이 없어 이번 사용자 현상의 직접 원인이라고 단정하지 않는다.

원인: 모든 초기 hash를 deep 링크로 취급해 reach()에서 hero를 이미 본 것으로 표시하고, hero 시작 조건에서도 제외했다. 수정은 #intro만 정상 첫 화면으로 취급하고 실제 본문 목적지의 즉시 가독성은 유지한다.

추가 개선: 앞선 안내는 첫 화면 버튼을 눌러야 효과가 보이는 경로였다. 명시적으로 효과를 보겠다는 접속 링크 `?motion=on`을 제공해 해당 링크에서는 기기 설정이나 이전 사이트 off 선택 때문에 효과가 가려지지 않게 한다. 사이트 선택만 저장하고 query는 현재 history 항목에서 소비해 지운다. 이후 끄기와 새로고침 선택을 존중하며 운영체제 설정은 변경하지 않는다. 일반 접속의 모션 축소 초기 비활성은 유지한다.

Claude Code가 기존 JS 한 파일에서 #intro의 초기 reach 제외와 시작 조건, 명시적 링크 처리만 수정했다. HTML·CSS·기존 패널 형상·모바일 메뉴는 변경하지 않았다. Codex가 빌드·정적 검사와 확장한 점진적 향상 17개 검사를 통과했다. 두 언어에서 모션 축소 상태의 `?v=entry&motion=on#intro`는 hero 애니메이션 7개를 시작했고 v·hash는 보존하며 motion만 소비했다. 같은 #intro 새로고침에서도 7개였고 끈 뒤 새로고침에서는 off를 유지했다. 기존 본문 직접 링크 가독성은 별도 Firefox 검사로 확인한다. 사용자 접속 주소는 아직 확인하지 못했으므로 사용자 현상과의 동일 원인을 단정하지 않는다.

사용자가 이후 “화면 효과 켜니까 잘 보이네”라고 직접 확인했다. 기존 효과가 전혀 보이지 않던 상황은 켜기로 해소됐고, #intro의 별도 진입 오류 수정은 유지한다. 이어진 투명도·자연스러운 흐름 추가는 새 기능 개선으로 T06에 기록한다.
