# I009 — 보고서의 실제 제외 커밋 상세 누락

상태: 해결·로컬 PDF 재검증 완료. 2026-11-04 KST. 최초 발견은 수정 전 별도 커밋 `daa5ac9`에 보존했다.

## 관찰과 재현

main `28dc95b6b8d3d93bc7cd8ff6a19de0dad89afda4`에서 공개 검사 후 `scripts/collect_release.py`, `scripts/render_records.py --release ... --identity ...`로 보고서를 생성했다. 보고서 4절은 후보 71개·제외 2개·유효 69개와 일반 제외 규칙을 적었으나, 실제 제외 대상 두 건의 SHA·개별 이유를 모두 적지 않았다. `submission/release.json`에는 상세 정보가 있지만 LMS 제출물은 PDF 한 개다.

## 기대 결과와 영향

원본 공개 채점기준 10쪽의 집계 근거에 맞춰 PDF 안에서 실제 제외 SHA 또는 범위·유형·이유를 확인할 수 있어야 한다. 현재 PDF는 기본 원본 등록 SHA만 설명하고 PDF 자동 생성 커밋의 SHA를 누락하여 상세 근거가 외부 로컬 파일에 의존한다.

## 원인 판단

`docs/report-sections.json`의 4절에 일반 제외 규칙과 JSON 보존 위치만 적고, 실제 제외 목록을 넣지 않았다. 집계 알고리즘의 수치 오류는 관찰하지 않았다.

## 수정 전 근거

제외 대상은 `1954a8b29c7c3a5435ec30238c9f9be2090e3b97`(원본 ZIP·준비 결과 단순 등록)와 `869ff6f167048883c485c5eca14654f5eb756a87`(TASK PDF만 자동 생성)다. 개인정보가 있는 제출 PDF는 공개 Git에 넣지 않는다.

## 수정과 재검증

`scripts/render_records.py`에서 release의 실제 `included=false` 항목을 읽어 전체 SHA와 이유를 `EXCLUDED_DETAILS`로 치환한다. `docs/report-sections.json`의 4절에 이 목록을 출력한다. 제외가 없으면 0개라고 표시한다.

동일 release로 실제 PDF를 재생성했다. 본문 추출로 두 제외 SHA가 모두 들어가고 미치환 토큰이 없는 것을 확인했으며, 렌더링한 4쪽에서 전체 SHA·이유가 잘림 없이 읽히는 것을 확인했다. 후보 71·제외 2·유효 69라는 수치는 수정하지 않았다. 최종 배포 뒤 집계 수치·제출 SHA를 다시 수집하여 PDF를 갱신한다.
