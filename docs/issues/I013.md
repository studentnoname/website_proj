# I013 — 기본 브라우저에서 화면 효과가 꺼지고 다시 켤 수 없음

상태: 수정·로컬 재검증 완료. 2026-11-04 KST. 수정 전 기록: `c462b52`.

사용자가 공개 사이트에서 변화가 없다고 보고했다. 별도 Firefox 프로필에서 `ui.prefersReducedMotion`을 설정하지 않고 공개 주소를 열었다. 결과는 `reduced: true`, 저장된 사이트 선택 `null`, `data-pf-motion: off`, 준비된 패널 0개였다. 네 패널 모두 일반 흐름이었다. 배포 누락이 아니라 이 PC의 기본 동작 줄이기 요청으로 효과가 비활성화된 것이다. 사용자 개인 프로필은 읽거나 변경하지 않았다.

기존 검사는 보통 동작 검사에 `ui.prefersReducedMotion=0`을 강제로 지정했고, 동작 줄이기 검사에서는 효과가 꺼진 것만 확인했다. 실제 기본 설정에서 사용자가 의도적으로 다시 켤 수 있는지는 확인하지 않았다. 현재 버튼은 하단에만 있고 동작 줄이기에서는 `aria-disabled`와 클릭 차단으로 켤 수 없다.

수정 방향: 시스템 설정에 따른 초기 비활성은 유지한다. 첫 화면에도 동일한 효과 제어를 제공하고, 사용자가 명시적으로 켜면 사이트 안에서만 활성화한다. 시스템 변경은 저장된 허용을 초기화해 다시 비활성화한다. 효과를 켜는 즉시 현재 첫 화면의 등장도 재생한다. 일반/동작 줄이기/명시적 켜기/끄기/재접속/실시간 변경을 검증한다.

Claude Code가 기존 프론트 세 파일을 수정했다. 첫 화면·하단 제어는 함께 동기화되며 버튼이 비활성화되지 않는다. 켜기에서 첫 화면에 있으면 850ms·120ms 간격의 등장을 재생한다. CSS의 중복 시스템 조건을 제거하고 JS가 정한 상태로 패널을 활성화한다. 시스템 모션 설정이 실행 중 바뀌면 저장된 사이트 선택을 지우고 시스템 설정을 따른다.

Codex가 빌드·정적 검사와 기존 Firefox 55개 검사를 통과했다. 점진적 향상 검사를 11개로 확장했다. 동작 줄이기 초기 비활성, 두 언어 첫 화면 버튼의 명시적 켜기·네 패널 준비·실제 위/아래 hit-test·곡선 clip·다시 접속 시 유지·키보드 끄기와 기본 시스템 설정을 확인했다. 기본 시스템 검사는 강제 override 없이 실행했고 실제로 reduced=true였다. 기기 설정을 변경하지 않았으며 실제 Safari/iPhone 검사는 하지 않았다.
