# I007 — Firefox 검사 도구가 실제 뷰포트와 초기 상태를 오판

- 상태: resolved
- 발견: 2026-10-29 KST, 첫 자동 브라우저 검사.
- 실제: Windows Firefox는 요청한 390px 창을 500px로 제한했다. Ctrl+plus 입력은 브라우저 확대에 반영되지 않았고, 이미 시스템 설정으로 정지된 움직임 제어를 클릭해 반대 상태가 됐다.
- 기대: 실제 390px 뷰포트와 실제 200% 확대를 검증하고 버튼의 초기 상태를 고려해야 한다.
- 영향: 첫 검사 결과를 390px·200% 통과로 사용할 수 없다. 1440px·768px 배치, 키보드·메뉴·뒤로 가기·언어 앵커 검사는 별도로 성공했다.
- 다음 조치: 검사 전용 Firefox의 chrome context에서 최소 창 크기와 실제 브라우저 확대를 설정하고, 제어 버튼은 이전 상태에서의 전환을 검사한다. 사용자 기본 프로필은 사용하지 않는다.
- 수정: 전용 검사 프로필의 browser 요소를 실제 390px 콘텐츠 폭으로 제한하고 `innerWidth`를 확인했다. Firefox ZoomManager로 2배 확대를 설정하고 DPR 1→2·너비 1440→720을 측정했다. 움직임 버튼은 초기값과 반대값을 비교한다.
- 재검증: 두 언어 1440·768·390px, 모바일 메뉴·Escape·폭 복구, 앵커·뒤로 가기·언어, 키보드·200%·움직임의 20개 검사가 모두 통과했다. `docs/evidence/T08/firefox/results.json` 참조.
